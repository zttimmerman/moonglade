## Context
See ADR-0011 (accepted for Phase 1) and docs/research/second-stack-spike.md (collision table in the ADR draft history; memory numbers). Phase 1: no real client in lane B.

## Decisions
- `paths.py` reads `HS_LANE` once. Lane B overrides RUN/LOGS/TMP/ETC/datadir/ports/Wine prefix. Player paths and the run registry dir stay global.
- Template datadir `env/lanes/b/template` built by `hs lane init` (`mysqld --initialize-insecure` + AutoSetup on lane-B ports). Each run uses an APFS clone (`cp -c`) as `env/lanes/b/mysql`. The player's datadir is never read.
- worldserver/authserver confs are rendered into lane B's etc. Module and DB keys for lane B go in as `AC_*` env vars in `stack._spawn` (union of all profiles' keys). `config.render` writes atomically.
- Process matching: auth/world by `-c <lane etc>`; mysqld already by its my.cnf. The Wow rule in launch.py requires a prefix match.
- Realmlist row port comes from P (fixes the hard-coded 8085).
- Scheduler: `hslib/lanes.py` (LANE_B table, split, memory preflight) plus `python -m hslib.lane spec.json` worker (HS_LANE=b, reuses runner.execute). Barriers: start after order < 34; join before order ≥ 380, any gui/app check, and order ≥ 998. Worker timeout kills its process group, and B is torn down.
- Initial LANE_B (Phase 1, per ADR): stand-in `play.*` (loop_clean_exit, interrupt_clean_exit, client_crash_cleanup, startup_failure, single_instance, offline, player_account), `report.tiers`, `comp.*`, `era.*`, `lifecycle.persist`. The builder may drop any that turn out to depend on lane-A-only state, recording why.
- Timing: `report.timing` compares per-check times under a lane-mode label. Re-join the baseline after the first clean two-lane full run.

## As built: lane layer (task group 1)
- `paths.py`: `HS_LANE` read once; `layout(lane)` gives every per-lane path/port; module constants are the current lane's. Lane-B paths: `env/lanes/b/{run,logs,tmp,etc,mysql,template,my.cnf,client*.cnf,wineprefix-<layer>}`. Shared: `GLOBAL_RUN/harness-runs` (run registry), player paths, `server/`, client data. `lane_refusal()` allows lane B only with `HS_HARNESS_RUN=1` and an `HS_HARNESS_RUN_ID` naming a live run file (pid + start time); `hs` (all commands but `lane status|down`), `./play` and `stack.up()` refuse; an unknown `HS_LANE` value exits at import.
- `config.write_all` (lane B): auth/world confs in `env/lanes/b/etc`, module confs mirrored there for readers, and `etc/ac-env.json` = AC_* for the union of every profile's module keys (profile value, else `.conf.dist` default) + `PlayerbotsDatabaseInfo` + `CommandServerPort=0`; `stack._spawn` adds them (and strips any inherited AC_*). `RealmServerPort`/`WorldServerPort` rendered from P in both lanes. Renders are atomic (temp + rename).
- `stack.stack_processes(lane)`: mysqld by `--defaults-file=<lane my.cnf>`, auth/world by binary + `-c` path (no `-c` = lane A). Lane-B `mysql_up` clones the template when the datadir is missing; only `hs lane init` may `--initialize`.
- `lanestack.py` (`hs lane init|status|down|reset`): from lane A each action re-runs itself with `HS_LANE=b`. `init` clones lane A's Wine prefix (only with A's Wine stopped), builds the template from scratch (~80 s), clones it. `reset` = down + fresh clone (~0.1 s).
- Orphan healing (`runreg.heal`): stops orphan lane workers (argv token `hslib.lane`) first, then per lane: this lane as before, other lanes via `runreg.lane_down(lane)` only when every process of that lane is an orphan.
- Lane-aware GIVENs: `play_checks.play_processes(lane)` by the process's `HS_LANE`; `launch.prefix_processes(prefix=)`, Wow rule needs a prefix match; `nightly.busy` covers both lanes. Lane B never writes `env/player.json` (needs `HS_PLAYER_FILE`) or `env/settings.json`.
- Checks `lane.*` sit at order 32-33, before the scheduler's start barrier (34), and drive lane B themselves.

## As built: scheduler, checks, timing (task groups 2-3)
- `lanes.py`: the reviewed `LANE_B` table (id -> why it's safe in B), the table rules (`forbidden`: gui, `app.*`, `client.stock_mode`/`launch_smoke`, build/baseline/setup, `pop.*`/`perf.*`, player-protection incl. `backups.*` and order >= 998, `lane.*`/`report.*`, outside [34, 380)), the memory probe (`kern.memorystatus_vm_pressure_level`, `vm_stat` free+inactive+speculative+purgeable, `vm.swapusage`), `preflight_decision`, `midrun_stop` and `schedule()`.
- `hs run --lanes 1|2`. Default: 2 for unfiltered full/slow runs, 1 for quick, gui, backups and **every filtered run** (short runs: lane B's stack start-up would cost more than it saves; `--lanes 2` opts in). `--lanes 1` is the old `execute()` call, unchanged.
- `schedule()`: lane A runs the checks with order < 34; then the preflight; then `python -m hslib.lane <spec>` (HS_LANE=b, same run id, own process group) runs the B checks while A runs its checks up to the join point (the first executed check with order >= 380, gui, `app.*` or order >= 998; none = before the post-run checks). At the join A waits for the worker (timeout 3600 s: kill its process group, then `runreg.lane_down("b")`), merges its records (marked `"lane": "b"`), runs any B check that didn't finish (mid-run stop, worker failure or timeout) in A, then the rest. All records are sorted by (order, id).
- Preflight (ADR-0011 thresholds): measured **with lane A's stack up**; when A's stack is down at the barrier and the probe is real, the scheduler brings it up first (in a full run it is already up after `lane.orphans`). Measured 2026-10-08 on the 16 GB Mac: 6.96 GB available with A down, 5.57 GB with A up 45 s, so projecting A's 4.6 GB peak instead of measuring would have refused every run. Pressure level 1, >= 5 GB available, swap >= 1 GB free or grown <= 1 GB since the run started; power: refused on battery power or below 50 % plugged in (`--ignore-power` skips the power part). An unreadable probe refuses.
- Worker: `lanestack.reset()` (fresh template clone), then per check: memory probe (`midrun_stop`: pressure >= 2, swap growth > 1.5 GB, unreadable), battery below the power guard's pause level (35 %), parent run gone; any of them stops it before the next check. It rewrites a state file after each check, so the parent knows what finished; at the end `lanestack.down()`. The run's power guard stays in lane A (pauses/stops between A's checks); a power stop kills the worker and downs lane B. A killed parent: the worker's next lane-B `hs` command is refused (the run is dead), it downs B at its end, and the next run heals the rest (verified by SIGKILL, see the builder report).
- `meta.lanes`: requested/default/lanes/mode, `assignment` {b_planned, b_ran, b_to_a}, `preflight` {allowed, reasons, inputs (memory, memory at run start, A up, battery), thresholds}, `fallback`, `b` {wall_s, rc, timed_out, killed, stop, error, timeline, prepare, down}, `barriers` {joined_before, joined_at}, `timeline_a`. summary.md has a `Lanes:` line. results.schema.json requires `meta.lanes`.
- Test switches (`lanes.TEST_ENV`, nested `hs run` only; `hs` other commands, `./play` and `./bootstrap` refuse them): `HS_TEST_LANE_MEMORY` (stub readings, preflight + per-check mid-run sequence), `HS_TEST_LANE_B` (forced lane-B set, still subject to the table rules), `HS_TEST_LANE_TIMEOUT_S`. Read once and removed from the run's environment.
- Checks: `lane.table` (quick; plus a self-test table of one forbidden check per kind), `lane.merge` (full; nested `--lanes 2` vs `--lanes 1` over era.default_on, era.xp_curve | gm.server_info, sql.world_populated | client.player_config_untouched; memory and battery stubbed healthy so it tests scheduling, not this Mac's memory), `lane.preflight` (full; decision table + three nested runs with the B set forced to client.config_gen, client.inspect: low memory, battery 40 %, pressure 2 after B's first check), `report.lanes` (post-run: meta.lanes agrees with the records on every run, a two-lane worker failure/timeout fails; on an unfiltered full/slow run lane B ran every LANE_B check, and the wall time is recorded next to the last serial full run's from `harness/out/full-run-walls.json` or the kept last full run; a preflight refusal is "GIVEN not met", `--lanes 1` "not evaluated"), `lane.refusal` gains the three switches x (`hs run`, `hs up`, `./play`, `./bootstrap --check`, `hs up` with HS_HARNESS_RUN=1).
- Timing (3.2): `report.timing` compares like with like: `meta.lanes.mode` 1 against `checks`, 2 against `checks_lanes2` in `harness/timing-baseline.json`; a two-lane run with no two-lane baseline is "not evaluated" (summary line), never compared with serial times. `hs timing-baseline join` puts a two-lane run's checks in `checks_lanes2` (the first join adds every executed check; run labels carry `lanes`). Synthetic cases h-j in report.timing cover it. The orchestrator joins the first clean two-lane full run.
- Dropped from the initial LANE_B: **report.tiers**. It is a post-run check, after the join by construction, and its nested quick tier (a) has a 180 s budget it already uses 135 s of serially, so contention would make it flaky, and (b) runs app.bundle_valid (rebuilds dist/Moonglade.app, kills stale test launchers), re.* (shared env/re) and client.play_build alongside lane A. `play.player_account_untouched` (player protection) was never in it. Every other ADR Phase-1 entry is in.
- Expected saving: B's checks took 549 s serially (last full run); lane A's checks in B's window took 264 s with the backups tier skipped, 798 s with it. So a full run saves about the A-window time (~4-5 min) when backups are skipped, and B's time (~9 min) when they run, minus contention.
