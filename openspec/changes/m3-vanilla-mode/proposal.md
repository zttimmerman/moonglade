# Proposal: M3 Vanilla mode (era profile)

## Why
Gate 1 was signed on 2026-10-01 (`docs/gate1-era-profile-memo.md`, Decisions). Zach wants levels 1–60 to play with pre-2.3 ("vanilla") pacing and difficulty, **on by default and easily toggleable**, with all WotLK content and systems intact.

## What Changes
- A new AzerothCore module, `modules/mod-era-profile`. It's an AzerothCore module only: VMaNGOS is a read-only data source (CLAUDE.md §7), and no VMaNGOS code is used.
- **Side tables** in the world DB (`era_*`) hold the vanilla values for each in-scope entity, next to a captured WotLK baseline. Every row cites its source (VMaNGOS snapshot ID, table, entry).
- They're generated by `tools/era-diff` (extended to emit SQL), so no value is ever typed by hand.
- One config line, `EraProfile.Enable` (default **1**), switches all of the signed items together:
  1. XP per level 11–59: vanilla (the L60 row stays WotLK).
  2. Quest XP: vanilla, through the module's quest-XP hook. Rows within ±5% and unmappable rows stay WotLK.
  3. Outdoor elites: vanilla rank plus HealthModifier for the 1–60 open-world creatures in the diff. Damage and armor are not changed.
  4. Mounts & riding: vanilla required levels and prices for vendor mounts, and vanilla level and cost for Apprentice/Journeyman riding.
- How a switch takes effect: the runtime hooks where AzerothCore offers them; otherwise the module applies or reverts against the baseline at server start. Flipping the setting takes effect on the next restart, and character progress is untouched. The design keeps a later no-restart, in-game, per-character menu possible (backlog).

## Capabilities
### New Capabilities
- `era-profile`: vanilla-mode pacing and difficulty for levels 1–60, switchable, with WotLK content provably untouched.

### Modified Capabilities
(none)

## Impact
New module (static, built in by `hs build` via `modules/`), new world-DB side tables, an era-diff SQL generator, new checks. A core patch is a last resort and needs an ADR.

## Data provenance
All values come from the VMaNGOS SQLite snapshot `db-sqlite-4641790` (pinned in `fork.lock`) through `tools/era-diff`. Example entities in the scenarios come from the Gate 1 memo, which itself comes from tool output. Open item from the memo: what VMaNGOS `RewXP` means (the full XP at quest level) is assumed. The builder must confirm it from VMaNGOS source before quest XP ships, or flag it and leave quest XP pending.
