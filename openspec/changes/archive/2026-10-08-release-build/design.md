## Research summary (Plan agent, 2026-10-08)
- **Server dylib closure:** libmysqlclient.24; boost (filesystem, program_options, iostreams, random, thread, atomic, chrono, date_time, container); openssl@3; readline (worldserver only); transitive xz, zstd and zlib. About 15 MB. Both binaries carry an LC_RPATH to the dev `server/lib`.
- **mysqld:** Homebrew's links ~80 abseil dylibs plus ICU and protobuf. Use Oracle's official arm64 tarball instead: it uses @rpath and ships its own SSL. The CI server build uses its headers and lib, so the client lib matches.
- **Python:** the harness is stdlib-only and needs ≥3.10. `/usr/bin/python3` is a Command Line Tools stub, so it can't be used. Use python-build-standalone 3.13 install_only_stripped (~18 MB compressed).
- **Downloads:** Wine (WoWSilicon r17) and client-data stay first-launch downloads (LGPL source obligations and Blizzard-derived data stay off our release).
- **Compiled-in `_CONF_DIR`:** release servers get module keys as `AC_*` env (proven in lane B, ADR-0011). That belongs to `release-first-launch`; this change only records the conf-dist files.
- **SQL source dir for the DB updater:** core `data/sql/base` + `updates`, playerbots `data/sql`, and our modules' sql; not old/ or archive/. ~45 MB compressed.
- **Estimated download:** ~120 MB.

## Decisions (orchestrator, 2026-10-08)
- **Oracle MySQL, version:** 8.4 LTS unless the dev stack's 9.x schema/updater needs 9.x; the builder checks and records which. Dev parity is a later follow-up.
- **readline:** off (`-DWITH_READLINE` or equivalent); friends never use the server console. This avoids shipping a GPL-3 source.
- **zip now, dmg later:** the dmg comes with `release-signing` if Zach picks Developer ID.
- **DB template:** not in this change. Measure the first-start split (SQL import vs bot setup) in `release-first-launch` first.
- **CI:** the workflow file lands now and is validated locally (actionlint if available via pip, else a YAML schema check). It runs on GitHub only after the repo is public.
- **Local packaging runs on this Mac:** a portable build in `env/release/build` with ccache (power guard applies, `--jobs` default). Oracle MySQL and PBS are downloaded into `env/release/cache`. Never `brew install` locally: CI installs build deps on the runner; locally the existing Homebrew deps are used read-only for the build, and delocate copies them into the payload.
- **"Runs without Homebrew" locally:** `sandbox-exec` with a deny-read profile for `/opt/homebrew` and `/usr/local`. No system changes; the CI smoke additionally moves Homebrew aside on the runner.

## As built (builder, 2026-10-08)
- **Pins** (`fork.lock` `release_*`, `harness/hslib/downloads.py` PINS `release-mysql`, `release-mysql-source`, `release-python`, `release-python-licenses`): Oracle MySQL **8.4.11** LTS (`mysql-8.4.11-macos15-arm64.tar.gz`; 8.4.12 was a docker-only CPU release with no macOS tarball). AzerothCore needs ≥ 8.0 and the harness's my.cnf uses nothing 9.x-only, so 8.4 stays. Oracle publishes MD5 + GPG, not SHA-256: the pinned sha256 was computed from downloads whose MD5 matched Oracle's `.md5` files (GPG not checked; no gpg here). python-build-standalone 20261003, CPython 3.13.16 `install_only_stripped`; sha256 from its SHA256SUMS. The same build's `pgo+lto-full` archive is pinned too, only for its `licenses/` folder (texts of every library linked into python). Packaging fetches through `downloads.obtain` (cache `env/release/cache`), so a mismatch is refused, the bad file removed, and packaging stops naming the pin before anything is built.
- **Portable build** (`tools/release/release.py` step `build`, driven by `tools/release/package.sh`): cmake tree `env/release/build/cmake`, install `env/release/build/install`, `CONF_DIR=etc` (relative, so no absolute config dir is compiled in), `CMAKE_OSX_DEPLOYMENT_TARGET=26.0`, `-ffile-prefix-map` for the repo and `/opt/homebrew` (no source paths in the binaries), Oracle's headers, `libmysqlclient`, `mysql_config` and `mysql` (never Homebrew's; checked in `compile_commands.json` and `otool`), ccache, the harness's power guard and default job count. vendor/ is read, never synced, unless `--sync-vendor` (CI). AzerothCore sets its own install rpath (the absolute install `lib/`), so `-DCMAKE_INSTALL_RPATH` alone doesn't stick; delocate sets exactly `@executable_path/../lib`.
- **readline off:** AzerothCore has no switch for it (readline is mandatory on Unix, `deps/readline`), and macOS's libedit lacks `rl_event_hook`/`rl_done`. Instead of a core patch, `tools/release/readline-stub` (our code, GPL-2.0-or-later) implements exactly the readline API `CliRunnable.cpp` uses as a plain line reader and is linked statically via `READLINE_LIBRARY`. No GPL-3 readline ships; the console still accepts typed commands, without editing/history/completion.
- **Payload** (`env/release/payload/Moonglade`, ~610 MB unpacked): `server/{bin,lib,etc}` (14 bundled dylibs: boost ×9, OpenSSL 3.6.5 from Homebrew, xz, zstd, Oracle libmysqlclient; Oracle's own libssl/libcrypto are deduplicated onto the server's, OpenSSL 3 keeps ABI within 3.x), `mysql/` (Oracle's signed `mysqld`, `mysql`, `mysqldump` unmodified, plus only the dylibs they load: libssl, libcrypto, libprotobuf-lite; `share/english`, `share/charsets`), `python/` (pruned: no tk/tcl, tests, pip, headers, libpython), `harness/ play bootstrap patches/ client-mods/ branding/ fork.lock LICENSE NOTICE README.md` from the commit (git archive of HEAD, so the payload equals the source asset), `sql/` (core `data/sql/{base,create,custom,updates}`, playerbots `data/sql` under `sql/modules/mod-playerbots/`, our modules' `data/sql`, all from the pinned-commit-plus-patches trees), `bin/{Moonglade,hsdock.dylib}` (prebuilt launcher and Wine host shim), `THIRD_PARTY/` (INDEX.json maps every bundled library to its licence folder), `VERSION` (JSON: version, commit, pins, trees). The harness is importable as `python/bin/python3 -I -m hslib` through `site-packages/moonglade-harness.pth` (a relative path, so it survives moves).
- **delocate.py** `fix` copies the closure, rewrites to `@rpath/<name>`, sets library rpath `@loader_path` and executable rpath `@executable_path/../lib`, re-signs ad hoc; `gate` refuses forbidden load commands/install names/rpaths and unallowlisted path strings. `tools/release/allowlist.json` holds 11 reviewed string entries (AzerothCore's revision.h defaults for SourceDirectory/MySQLExecutable/BuildDirectory/CMakeCommand, OpenSSL's compiled-in OPENSSLDIR/ENGINESDIR/MODULESDIR in both libcryptos, Oracle MySQL's `/usr/local/mysql/...` defaults and test-fixture strings, CPython docstrings, the launcher's PATH list). Locally the revision.h defaults name this Mac's repo path; CI builds name the runner's workspace. `release-first-launch` must set SourceDirectory and MySQLExecutable (and should set OPENSSL_CONF).
- **Assets** (`env/release/out`): `Moonglade-<version>-macos-arm64.zip` (ditto; 164 MB on 2026-10-08, dominated by the SQL), `moonglade-<version>-source.tar.gz` (HEAD), `azerothcore-<sha12>-with-patches-source.tar.gz` and `mod-playerbots-<sha12>-with-patches-source.tar.gz` (git archive of the pinned commit + patches tree), `mysql-8.4.11.tar.gz`, `SOURCES.json`, `SHA256SUMS`. "The download" in the spec is the zip; the source assets add ~720 MB (MySQL source 479 MB).
- **Smoke** (`tools/release/smoke.py`, stdlib, runs under the payload's own Python in CI): sandbox-exec profile denying reads of `/opt/homebrew` and `/usr/local` and writes under the repo except the scratch dir (proven by `ls /opt/homebrew` failing under it), a random free port that isn't a lane's, mysqld `--no-defaults --initialize-insecure` + start + `SELECT VERSION()` + `SHUTDOWN`, `worldserver/authserver --version`, `python -I -m hslib --help` and hslib's origin, at "Place One" and again after a move to "Second Place".
- **CI** (`.github/workflows/release.yml`): tag push `v*`, `if` the repo is public, `macos-26`, actions pinned by commit SHA, `brew install` on the runner only, ccache and download caches, `package.sh all --sync-vendor`, size gate, Homebrew moved aside for the smoke, then `gh release create --draft`. Validated locally with actionlint 1.7.12 (pip `actionlint-py` in `env/tools/actionlint-venv`); never run.
- **Checks** (`harness/hslib/checks/release_checks.py`, order 13): `release.pins` (full tier; ~2 s with a warm cache) and five slow-tier checks sharing one `package.sh all` per harness run (~80 s incremental; a from-empty portable build took 742 s here with a cold ccache for these flags): `dev_untouched`, `no_abs_paths`, `runs_without_homebrew`, `no_game_files`, `source_alongside`. Game-file patterns ignore git's empty `.gitkeep` markers (AzerothCore's `var/extractors/{maps,...}/.gitkeep`) and source folders like `src/.../Maps/`.
